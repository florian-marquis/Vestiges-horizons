# ADR-001 : Gestion des débordements dans les calculs économiques

## Statut
**Accepté**  
**Date** : 2024-11-14  
**Auteurs** : Agent IA (Mistral Vibe)

---

## Contexte

Le projet utilise exclusivement des entiers (spec §3 : "Tout est entier") :
- Monnaie : centimes (1 unité = 100)
- Pourcentages : millièmes (100 = 10%)
- Temps : jours

Les calculs économiques (prix, intérêts, taxes, coûts) impliquent des multiplications qui peuvent facilement déborder `u64` :
- Exemple : `1_000_000_000 * 100 * 1000 = 100_000_000_000_000` (> u64::MAX)

---

## Décision

**Utiliser une approche défensive en couches :**

### Couche 1 : Prévention (Design)
- **Pourcentages en millièmes** : Toujours stocker les taux en entiers (ex: 10% = 100)
- **Échelle adaptée** : Diviser tôt pour réduire la magnitude des calculs
  ```rust
  // ❌ Risque de débordement
  let result = (value * percent * 1000) / 100000;
  
  // ✅ Division précoce
  let result = (value / 1000) * percent / 100;
  ```

### Couche 2 : Détection (Runtime)
- **`checked_mul`** pour toutes les multiplications entre variables non bornées
- **`checked_add`** pour les additions critiques
- **Fallback explicite** : Retourner `u64::MAX` ou une valeur plafond spécifique
  ```rust
  let part1 = a.checked_mul(b);
  if let Some(p1) = part1 {
      let part2 = p1.checked_mul(c);
      p2.unwrap_or(u64::MAX)
  } else {
      u64::MAX
  }
  ```

### Couche 3 : Saturation (Acceptation)
- **`saturating_add`** pour les accumulations (ex: somme de montants)
- **`saturating_sub`** pour les soustractions (ex: remboursement de prêt)
  ```rust
  // Pour une somme de montants
  self.total = self.total.saturating_add(amount);
  
  // Pour une soustraction
  self.remaining = self.remaining.saturating_sub(payment);
  ```

---

## Conséquences

### Positives
- **Sécurité** : Aucun risque de panic dû aux débordements
- **Déterminisme** : Comportement prévisible même en cas de dépassement
- **Conformité** : Respect strict de la spec §3

### Négatives
- **Code plus verbeux** : +10-20% de lignes par calcul
- **Performances** : Légère surcharge due aux vérifications

---

## Alternatives rejetées

### 1. Utiliser `u128`
**Rejeté car** : 
- Non supporté nativement par tous les environnements
- Sérialisation/désérialisation plus complexe
- Risque de cascade : si `u128` déborde, retour au même problème

### 2. Utiliser `BigInt`
**Rejeté car** : 
- Dépendance externe nécessaire
- Performances très inférieures
- Complexité de gestion

### 3. Ignorer les débordements
**Rejeté car** : 
- Violation de la spec §3 ("Tout est entier")
- Comportement non déterministe (wrap-around imprévisible)
- Risque de bugs silencieux

## Exemples concrets

### Calcul de prix (market.rs)
```rust
// ❌ Ancienne version (bug corrigé)
let price_increase = (slope * excess * 1000) / capacity;  // Débordement possible

// ✅ Nouvelle version
let part1 = slope.checked_mul(excess);
let price_increase = if let Some(p1) = part1 {
    (p1 / capacity).min(PRICE_ELASTICITY_CAP as u64)
} else {
    PRICE_ELASTICITY_CAP as u64
};
```

### Calcul d'intérêts (credit.rs)
```rust
// ✅ Version sécurisée
let part1 = principal / 1000;
let part2 = part1.checked_mul(interest_rate as u64);
let total_interest = if let Some(p2) = part2 {
    let p3 = p2.checked_mul(num_installments as u64);
    p3.unwrap_or(u64::MAX) / 1000
} else {
    u64::MAX
};
```
